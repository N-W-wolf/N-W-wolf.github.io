四足机器人是一套由感知、估计、决策、控制和执行组成的完整系统，强化学习只是其中一部分：它通常承担"运动策略"这一层，把机器人状态和任务指令映射为关节控制指令。本文是"四足强化学习与仿真"章节的第一篇，目标是先建立整体图景——策略在系统里处于什么位置、它负责什么、不负责什么，为后续的训练闭环、任务构建等文档打好框架。

## 基础概念

- **强化学习策略（Policy）**：一个从观测到动作的映射，通常用神经网络 $\pi_\theta$ 表示。运行时它不"理解"机器人，只是持续接收观测并输出动作。
- **本体感知（Proprioception）**：机器人对自身状态的感知，如关节编码器读数和 IMU 测量。仅依靠本体感知的策略就可以完成基础运动任务。
- **运动控制层**：软件系统中直接决定"十二个关节下一时刻如何动作"的层级，传统方法由步态规划和模型控制实现，强化学习策略是这一层的替代或补充方案。

## 1. 策略处于系统中的哪一层

回顾四足机器人的典型软件分层：

| 层级 | 典型内容 | 与强化学习的关系 |
| --- | --- | --- |
| 任务与导航层 | 接收用户指令、路径规划、避障决策 | 通常不涉及，作为外部指令来源 |
| 感知与状态估计层 | 融合 IMU、编码器，估计姿态、速度、接触状态 | 为策略提供观测输入 |
| **运动策略层** | 决定各关节的控制目标 | **强化学习策略所在的位置** |
| 执行层 | 关节驱动器内的电流环、通信与保护 | 不涉及，策略的输出最终交到这里 |

也就是说，强化学习策略并不"包办"整个机器人：上游的状态估计把传感器数据整理成策略能用的观测，下游的执行层把策略输出的指令变成电机力矩。策略本身只占据中间的推理环节。

## 2. 策略的输入与输出

运行时，策略以固定频率（常见 50 Hz）被调用一轮，完成一次"观测进、动作出"：

- **输入是观测（Observation）**：通常是拼接后的数值向量，典型内容包括速度或姿态指令、IMU 角速度、重力方向在机身坐标系下的投影、关节位置与速度、上一轮输出的动作等。观测具体由哪些项组成、顺序如何约定，见后续文档《Observation 与 State》。
- **输出是动作（Action）**：最常见的形式是十二个关节的目标位置偏移，叠加在默认站姿上后交给底层关节控制；也有输出目标力矩的方案。具体形式见《Action 与关节控制》。

值得注意的是，策略内部并不知道"这是机器人的左前腿"这类语义，它只看到一串有序的数字。因此观测的定义和排列方式是训练与部署必须严格一致的一份约定，这也是仿真任务构建部分反复强调对齐的原因。

## 3. 策略负责什么、不负责什么

从上面的位置可以划出清晰的边界。

策略负责的：

- 在给定的运动任务（如按指令速度行走）下，根据观测实时协调十二个关节；
- 适应传统方法难以显式建模的部分，如足地接触、地形变化和模型误差。

策略不负责的：

- **状态估计**：策略使用的机身姿态、速度等往往来自估计器，而不是策略自己算出来的；
- **任务决策与导航**：去哪里、走哪条路线属于上层逻辑，策略只接受速度等运动指令；
- **底层执行与安全保护**：电流环、温度与电流保护在驱动器或实时程序中实现，策略输出仍然要经过这些环节约束。

把"策略不会做的事"记清楚，在调试中非常重要：机器人摔倒可能不是策略的问题，而是估计错误、指令异常或执行层故障；反过来，训练指标再好也不能替代部署侧的安全检查。

## 4. 与传统运动控制方法的关系

同一层任务（运动控制）历史上主要由模型化方法完成：用步态规划安排落脚时序，用模型预测控制（MPC）或全身控制求解关节力矩。强化学习提供的是另一种思路：

| 对比项 | 模型化方法 | 强化学习策略 |
| --- | --- | --- |
| 获取方式 | 依据物理模型推导与人工调参 | 在仿真中通过大量交互训练得到 |
| 运行时计算 | 求解优化问题，计算量较大 | 一次神经网络前向推理，开销小且固定 |
| 对未知扰动的适应 | 依赖建模完整程度 | 可通过训练分布覆盖获得一定鲁棒性 |
| 可解释性 | 每步行为有明确的模型依据 | 内部决策过程难以直接解释 |

两者不是非此即彼的关系，工程中也存在混合方案（例如策略输出叠加在模型化控制器之上）。在本章节的后续内容中，我们主要沿强化学习路线展开：先在仿真中定义任务，再训练策略，最后讨论如何迁移到实机。

## 常见问题

- **"训练好了策略，机器人就能跑了吗？"** 不能。还需要一致的状态估计、正确的观测对齐、部署侧的安全限制，以及 sim-to-real 层面的处理，这些都属于后续章节的内容。
- **"策略能直接输出电机电流吗？"** 常见方案输出的是目标关节位置（或叠加在默认姿态上的偏移），由底层关节控制转换为力矩；直接输出力矩的方案对训练和安全性要求更高。
- **"策略需要知道自己在执行什么任务吗？"** 任务通过指令和奖励在训练阶段定义；运行时策略只看到观测中的指令项，不存在额外的"任务描述"。
