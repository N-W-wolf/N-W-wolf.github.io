强化学习与监督学习最大的区别在于：没有现成的"输入—正确答案"数据集，训练数据由智能体自己的行为产生。因此训练过程是一个不断重复的闭环——让策略与环境交互采样，用交互结果评价策略，再更新策略，然后回到新的环境继续采样。本文介绍这个闭环在四足机器人上的基本形态，并结合我们实际使用的 legged_gym + rsl_rl 训练框架，说明闭环的每一环节落在哪里、数据如何流动、如何判断训练是否正常。

## 基础概念

- **采样（Rollout）**：让当前策略在仿真环境中运行一段时间，记录每一步的观测、动作、奖励和转移结果。
- **更新（Update）**：利用采样数据按优化目标（如 PPO）调整策略网络和价值网络的参数。
- **On-policy**：采样数据必须来自当前策略，更新一次后旧数据就"过期"了，需要重新采样。我们使用的 PPO 属于这类算法。
- **回合（Episode）**：机器人从被重置开始，到摔倒或达到时长上限为止的一段连续交互，是评价策略的最小完整单元。
- **legged_gym + rsl_rl**：legged_gym 基于 NVIDIA Isaac Gym 提供的 GPU 并行仿真定义环境，rsl_rl 提供策略训练器（`OnPolicyRunner`），两者配合完成上述闭环。

## 1. 先形式化：闭环里流动的是什么

强化学习把交互过程描述为马尔可夫决策过程（Markov Decision Process，MDP）。每个控制时刻 $t$，策略 $\pi_\theta$ 按下述方式与环境交互：

$$
o_t \xrightarrow{\ \pi_\theta\ } a_t \quad,\quad
(o_t,\ a_t,\ r_t,\ o_{t+1},\ \text{done}_t)
$$

- 策略接收观测 $o_t$，输出动作 $a_t$（训练时按策略的随机性采样，而不是只取均值）；
- 环境根据动作推进物理，返回奖励 $r_t$ 和新的观测 $o_{t+1}$，并给出回合是否结束的标志 done；
- 一段连续交互就构成轨迹（trajectory），训练的目标是调整 $\theta$，使轨迹上的累计折扣回报 $\sum_t \gamma^t r_t$ 尽量大，折扣因子 $\gamma$ 通常取 0.99 左右。

"闭环"正是这个五元组数据的循环生产过程：策略产生轨迹，轨迹反过来改变策略。理解了这一点，后续所有算法（PPO、优势估计、价值函数）都只是在回答"如何用好这批轨迹数据"。

## 2. 一次训练迭代的完整拆解

rsl_rl 的训练以迭代为单位，每次迭代分成两个阶段。

### 2.1 交互采样阶段

训练启动时会创建 `num_envs` 个（常见默认 4096）互相独立的并行环境。采样阶段，所有环境以固定控制频率同步推进 `num_steps_per_env` 帧（rsl_rl 默认 24 帧），期间每帧都记录：

- 观测 $o_t$ 与动作 $a_t$；
- 动作的对数概率 $\log \pi_\theta(a_t \mid o_t)$（更新阶段要用）；
- 奖励 $r_t$、回合结束标志 done；
- 价值网络对当前状态的估值 $V(o_t)$。

以默认参数计，一次采样就产生 $4096 \times 24 \approx 98000$ 帧数据——这个规模监督学习要收集很久，而在并行仿真中只是一次迭代的固定开销。

采样期间还穿插两类对训练质量影响很大的机制：

- **指令与状态重采样**：各环境独立地在不同时刻重新随机指令、随机化扰动，保证一批数据覆盖大量任务状态；
- **课程推进**：地形课程按各环境的表现逐级解锁更难地形，机器人推搡扰动按周期施加（详见泛化与迁移一章）。

### 2.2 评价与更新阶段

采样结束后，用这批数据做一次策略更新，核心步骤：

1. **优势估计**：用广义优势估计（Generalized Advantage Estimation，GAE）回答"这一步的实际回报比价值网络的预期好多少"，GAE 在折扣因子 $\gamma$ 之外还引入参数 $\lambda$（约 0.95）平衡偏差与方差；
2. **PPO 目标优化**：把数据切分为若干小批量，进行若干轮（`num_learning_epochs`，默认约 5 轮）梯度更新，通过裁剪目标函数限制每次更新的幅度，使新策略不至于偏离产生数据的旧策略太远；
3. **辅助信号**：同时优化价值函数的回归损失，并在目标中加入熵奖励，防止策略过早收敛到单一动作模式；
4. **自适应学习率**：rsl_rl 会监测策略更新前后的 KL 散度，与期望值（`desired_kl`，默认约 0.01）比较后动态调整学习率——步子太大自动放小，太小自动放大。

更新完成后，这批数据即被丢弃（on-policy 的代价），策略带着新参数回到采样阶段。

## 3. 并行仿真与控制频率

有两个时间尺度容易混淆：

| 概念 | legged_gym 中的配置 | 典型值 |
| --- | --- | --- |
| 物理仿真步长 | `cfg.sim.dt` | 0.005 s（200 Hz） |
| 控制频率 | `cfg.control.decimation` | 每 4 个仿真步执行一次策略，即 50 Hz |

也就是说，策略每 50 Hz 给出一次 12 维动作，而两次动作之间物理引擎以 200 Hz 连续推进，并在每一步按 PD 控制律将目标关节角换算为力矩。这是策略"间接控制力矩"的实现基础。仿真本身以 headless 模式运行（不开渲染窗口），只在需要可视化时单独启动渲染进程，避免图形渲染拖慢采样。

环境数量并非越大越好：显存占用、批大小与超参数相互关联，通常先用较小规模（如几百个环境）跑通流程、验证任务定义，再放大规模正式训练。

## 4. 闭环在 legged_gym 中的对应

| 闭环环节 | legged_gym / rsl_rl 中的位置 |
| --- | --- |
| 任务与环境定义 | `legged_gym/envs/` 下的环境类（如 `LeggedRobot`）及其配置 `LeggedRobotCfg` |
| 并行仿真与物理计算 | Isaac Gym，环境数量由 `cfg.env.num_envs` 指定 |
| 控制频率与 PD 换算 | `cfg.control.decimation` 与 `cfg.control.stiffness` / `damping` |
| 单帧交互（观测 → 动作 → 奖励） | 环境类的 `step()`、`compute_observations()` 与奖励函数集 |
| 数据采集轮长 | `cfg.runner.num_steps_per_env`，每次更新前每个环境收集的帧数 |
| 策略与价值网络结构 | `cfg.policy.activation` 等配置，默认为 MLP |
| 策略更新 | rsl_rl 的 `OnPolicyRunner`（PPO），$\gamma$、$\lambda$、`desired_kl` 等在 `cfg.algorithm` 中配置 |
| 训练记录与存档 | 奖励分项、回合长度等写入 TensorBoard，模型按 `save_interval` 导出 |

配置采用"类内嵌套类"的组织方式，例如 `cfg.control.stiffness`（PD 增益）、`cfg.rewards.reward_scales`（奖励权重）、`cfg.algorithm.gamma`（折扣因子）都集中在对应的嵌套配置里。训练入口脚本通常只有几十行：解析配置、创建环境和 runner、调用 `learn()` 进入上述循环，真正的行为差异都由环境类和配置决定。这套"环境 + 配置"的组织方式决定了后续改任务大多是改配置和增删奖励函数，而不是改训练循环本身。

## 5. 如何判断闭环是否在正常工作

训练日志主要看几类信号，而不是只盯着总奖励：

| 信号 | 健康表现 | 异常信号及可能原因 |
| --- | --- | --- |
| 平均回合长度 | 随训练持续变长并趋于稳定 | 始终很短：频繁触发失败终止，查奖励与终止阈值；从不变化：可能从未触发重置 |
| 总奖励与分项奖励 | 各分项大体同步上升 | 某分项异常突出：可能被策略"钻空子"刷分，抑制了其他目标 |
| 价值损失 | 下降后稳定在较小值 | 持续不降或剧烈震荡：奖励量级失衡、折扣因子不合适 |
| KL 散度 | 在 `desired_kl` 附近小幅波动 | 长期偏离：学习率自适应异常或数据质量差 |
| 平均奖励标准差（策略噪声） | 随训练逐渐收缩 | 迟迟不收缩：策略仍在"探索"而未收敛 |

此外，**周期性查看渲染画面**是必要的习惯：指标正常但动作明显异常（如高频抖动、依赖特殊步态刷奖励）的情况并不少见，肉眼确认是最后一道检查。训练时间安排上，建议先跑几百次迭代确认曲线形态正常，再启动完整训练，避免数小时后才发现任务定义有误。

## 常见问题

- **"采样和更新哪个更重要？"** 两者耦合：任务和奖励决定采样出的数据好不好，算法和超参数决定数据能不能被有效利用。训练效果不好时，两个方向都要检查。
- **"为什么训练时动作要加随机性，部署时反而没有？"** 训练时按概率分布采样动作是为了探索更多行为；部署时通常直接取分布均值，行为更稳定。这也解释了为什么训练日志里的机器人和实际部署观感会有差异。
- **"环境数量是不是越多越好？"** 数量越多采样越快，但显存占用随之增加，且超过一定规模后收益递减；不同机器上通常先小规模验证、再放大正式训练。
- **"训练好的模型保存在哪里？"** rsl_rl 按保存间隔将策略权重导出为模型文件，部署阶段加载的就是这个文件，而不再是训练框架本身。
