上一篇描述了训练的闭环如何运转，但闭环里"环境"到底由什么构成，还没有展开。一个四足强化学习任务，本质上是对五个要素的一次完整定义：策略接收什么指令和观测、输出什么动作、按什么标准获得奖励、在什么情况下结束回合。这五个要素一旦定下来，"训练什么样的机器人"就定下来了。本文逐一介绍它们的设计考量，并说明各自在 legged_gym 框架中的位置。

## 基础概念

- **指令（Command）**：告诉策略"要做什么"的信号，例如期望的线速度、角速度，由训练程序按规则随机生成。
- **观测（Observation）**：策略每帧看到的数值向量，由机器人状态和指令按固定顺序拼接而成。
- **动作（Action）**：策略输出的数值向量，最常见的是叠加在默认站姿上的关节目标位置偏移。
- **奖励（Reward）**：每帧对动作好坏的标量打分，是任务目标的数学表达。
- **奖励权重（Scale）**：每个奖励项的系数，决定该项在总奖励中的相对重要性。
- **终止条件（Termination）**：判定回合结束的规则，包括摔倒等失败终止和到达时长上限的正常截断。

## 1. 指令：任务目标从哪里来

基础运动任务通常以速度指令表达。legged_gym 的默认配置使用 4 维指令：$x$、$y$ 方向线速度，偏航角速度，以及一个航向保持项。训练时没有人类下达指令，程序按配置的范围（如 $x$ 方向 $[-1, 1]$ m/s）均匀采样，并每隔固定时间（常见数秒）重新采样：

- **指令范围决定能力上限**：训练时没出现过的指令，部署时大概率执行不好，因此范围应覆盖预期使用场景而非盲目求大；
- **采样包含低速区间**：指令偶尔落在接近零的区间，策略才能学会原地站立和低速微调，否则会被迫永远运动；
- **中途变化迫使"跟踪"而非"记忆"**：指令在回合中重采样，策略无法预知下一秒的目标，只能学习从观测到动作的反馈规律；
- **航向模式的差别**：另一种常见定义直接给期望航向角而非角速度，由环境在内部换算，两者在观测上等价、在使用习惯上不同，改任务时需要留意。

## 2. 观测：策略看到什么

观测是把机器人状态"翻译"成策略输入的过程。典型四足运动策略的本体观测包括：

| 观测项 | 维数（典型） | 说明 |
| --- | --- | --- |
| 速度指令 | 3 | 期望线速度（x、y）与偏航角速度 |
| 角速度 | 3 | IMU 测量，乘缩放系数 0.25 |
| 重力方向投影 | 3 | 单位重力向量在机身坐标系下的投影，紧凑表达姿态 |
| 关节位置 | 12 | 编码器读数减去默认站姿 |
| 关节速度 | 12 | 乘缩放系数 0.05 |
| 上一帧动作 | 12 | 帮助策略感知自身输出历史 |

各分项乘以 `cfg.normalization.obs_scales` 中的缩放系数后再拼接，把不同物理量纲的数值拉到相近范围——关节速度原始值可达每秒十几弧度，不缩放会淹没其他分项。重力方向投影值得单独说明：它用 3 个数表达了完整的机身倾斜信息，避免了欧拉角的奇异问题和旋转矩阵的冗余，是姿态观测的常用技巧。

在此基础上还有两个重要机制：

- **观测噪声**：配置中的 `noise` 段为各观测项定义训练时叠加的噪声量级（通常按对应传感器精度的倍数给定）。策略是在带噪声的观测上训练的，否则会过拟合仿真给出的"完美数值"，上机后立刻失配；
- **观测历史**：部分方案把最近若干帧观测拼接成历史（`frame_stack`），让策略从序列中隐式推断接触状态和速度等信息。是否使用历史会影响网络输入维数和部署侧的推理逻辑，属于任务定义的一部分。

一个容易被忽略的设计约束是**部分可观测**：真实机身上没有"绝对速度传感器"，策略通常拿不到精确的线速度，能用的只有指令与估计器的输出。训练时若直接喂入真值，训练和部署的观测分布就不一致了，这正是后续 sim-to-real 章节要处理的核心问题之一。

## 3. 动作：策略如何控制关节

策略输出的 12 维动作不是力矩，而是经过固定链路换算的关节目标位置偏移：

$$
q_d = q_{\text{default}} + s \cdot \operatorname{clip}(a,\ -a_{\max},\ a_{\max})
$$

其中 $q_{\text{default}}$ 是默认站姿，$s$ 是动作缩放（`cfg.control.action_scale`，常见 0.25 rad），clip 把动作限制在安全范围内。目标关节角再交给框架内建的 PD 控制律换算力矩：

$$
\tau = K_p\,(q_d - q) + K_d\,(\dot q_d - \dot q)
$$

$K_p$、$K_d$ 在 `cfg.control.stiffness` / `damping` 中按关节组配置。这样设计有两个好处：把力矩计算交给成熟的 PD 层，策略只需学相对安全的姿态调整量；动作数值范围小且含义明确，训练更稳定。输出力矩的方案（常见于更激进的任务）则要求策略直接面对电机极限和安全性，训练难度显著上升。

## 4. 奖励：任务目标的数学化

奖励设计是四足任务定义中最花功夫的部分。legged_gym 的做法是把奖励拆成许多独立项：每项写成环境类中的一个 `reward_<名称>` 函数（返回该帧的瞬时奖励值），再通过 `cfg.rewards.reward_scales` 字典设置权重，框架自动按权重求和并乘以控制步长 `dt` 得到总奖励。常见的分项可以归为三类：

| 类别 | 奖励项（示例） | 鼓励什么 |
| --- | --- | --- |
| 任务项 | 线速度跟踪、角速度跟踪 | 机身实际速度贴近指令 |
| 规整项 | 姿态保持、关节速度惩罚、动作变化率、足部接触节奏 | 步态规整、动作平滑、能耗可控 |
| 安全项 | 躯干碰撞、关节超限、意外接触 | 避免伤害机器人本体与硬件的行为 |

权重就是设计者对目标的排序，三类之间经常互相牵制：跟踪精度与动作平滑冲突，能耗惩罚过重会让策略倾向于"趴着不动"。配置中的 `only_positive_rewards` 选项会把安全项以外的负奖励裁剪掉，避免过度惩罚导致策略"躺平"。此外，所有与"回合失败"相关的惩罚通常单独放在终止处理中，而不与逐帧奖励混在一起。

调奖励时还需要警惕**奖励钻空子（reward hacking）**：策略找到高分但不符合预期的行为。典型例子是原地上下抖动刷接触节奏分、依赖大幅摆腿刷速度分。定位方法就是查看分项记录——哪一项的贡献与整体行为明显不符，哪一项的定义就有漏洞。

## 5. 终止条件与回合重置

回合以两种方式结束，训练时的处理方式不同：

- **失败终止**：触发即判定本回合失败。基础任务中的条件通常是躯干（base）接触地面或地形高度超出阈值，可选的还有关节超限、姿态过度倾斜等；
- **正常截断**：回合长度达到 `cfg.episode_length_s` 换算出的帧数上限，属于"跑完了"而非"失败了"。截断时长通常设为指令重采样周期的整数倍，保证每个回合覆盖完整的指令序列。

两者的区分直接影响策略学到的行为：如果把截断也当成失败惩罚，策略会莫名回避长时间存活；反过来漏掉失败惩罚，则会放任摔倒行为。环境类中的 `check_termination()` 同时返回失败标志和截断标志，供更新阶段区别处理。

回合结束后由 `reset_idx()` 统一重置：机器人回到 `cfg.init_state` 定义的范围附近（位置、姿态、关节角都在小范围内随机，避免所有环境同步起跳造成数据相关），指令重新采样，课程与扰动的相关计数器同步更新。初始状态的随机化幅度同样是一种设计选择——完全固定会让策略只学一条"起步行"，过度随机则拖慢早期收敛。

## 6. 五要素如何串在一个控制步里

把五个要素放进 50 Hz 的一个控制周期（对应 `decimation` 个物理步），完整时序是：

1. 策略读取当前指令、带噪声的观测向量；
2. 输出动作 $a_t$，经 clip、缩放后叠加默认站姿，得到目标关节角；
3. 物理引擎以 200 Hz 连续推进若干步，每步按 PD 律计算力矩并施加扰动（如周期性推搡）；
4. 环境读取新的关节与机身状态，逐项计算奖励并加权求和；
5. 执行终止检查：摔倒则标记失败，达到时长上限则标记截断；
6. 触发终止的环境进入重置，其余环境构建下一帧观测，进入下一个周期。

这个时序把"任务定义"和上一篇的"训练闭环"连接了起来：闭环负责在迭代之间改进策略，五要素负责在每一帧内给出评价。

## 7. 五要素在 legged_gym 中的对应

| 要素 | legged_gym 中的位置 |
| --- | --- |
| 指令采样与重采样 | `commands` 配置段（范围、重采样周期）与环境类的 `resample_commands()` |
| 观测构建 | 环境类的 `compute_observations()`，缩放在 `normalization.obs_scales`，噪声在 `noise` 段 |
| 动作到关节指令 | `control` 配置段（`action_scale`、PD 增益） |
| 奖励函数与权重 | `reward_<名称>` 函数与 `rewards.reward_scales`、`rewards.only_positive_rewards` |
| 终止与重置 | `termination` 相关配置与环境类的 `check_termination()`、`reset_idx()` |

后续"仿真与任务构建"一章将按这五个要素分别展开，配合 legged_gym 的具体代码说明如何修改和扩展一个任务。

## 常见问题

- **"指令是人在训练时输入的吗？"** 不是。训练中指令由程序随机采样，训练完成后部署时才由上层（遥控器、导航模块）给出真实指令。
- **"为什么不给策略喂完整的真实状态（比如精确速度和接触信息）？"** 因为部署时拿不到。观测设计必须以实机上真实可得的传感器和估计量为上限，否则训练与部署的输入分布不一致。
- **"奖励项是不是越多越好？"** 不是。每增加一项就多一个需要权衡的自由度，且部分项之间互相冲突；通常从核心项（速度跟踪、存活、基础约束）开始，出现不期望行为时再逐项补充。
- **"摔倒惩罚是不是越重越好？"** 过重的惩罚会让策略在接近不稳定状态时过于保守，甚至学会"不冒险"，反而学不出有力的运动；一般用适度的负奖励配合存活奖励即可。
